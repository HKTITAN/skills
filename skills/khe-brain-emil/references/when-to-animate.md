# When to animate

His first question is never "which curve". It is whether the thing moves at all. Read [disagreements](disagreements.md) before quoting a line from here beside a line about springs.

## Purpose

- Ask what an animation is for before adding it. One with no purpose is not added. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Done well, motion makes an interface more predictable, faster in feel and more pleasant; done badly it makes it slow and annoying and costs the user's trust. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Explaining is a purpose: Linear's product animation in the first viewport explains a feature better than a still image. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- A second explaining example: Vercel's animation of how v0 works, which he calls both entertaining and informative. (Great Animations, https://emilkowal.ski/ui/great-animations)
- Feedback is a purpose: a button that scales down a little on press makes the interface feel alive and responsive. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Continuity and spatial logic are purposes: Sonner's toast animates in so it does not appear abruptly, and it enters and leaves along the same direction so the swipe to dismiss makes sense. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- A state change is a purpose: App Store cards, and a modal entering and leaving, are his examples. (Great Animations, https://emilkowal.ski/ui/great-animations)
- Animating everything overwhelms the user and weakens each animation; pace it and spend it where it adds information. (Great Animations, https://emilkowal.ski/ui/great-animations)
- The goal is an interface people are glad to use every day, never animation for its own sake. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)

## Frequency

- How often the user will see an animation is a deciding factor in whether it exists. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Check how often it is seen before adding it. (Great Animations, https://emilkowal.ski/ui/great-animations)
- Keyboard-initiated actions are never animated: they repeat hundreds of times a day, and motion makes them feel slow and disconnected from the keypress. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- The same rule, stated again as an absolute. (Great Animations, https://emilkowal.ski/ui/great-animations)
- Raycast opens hundreds of times a day with no open animation, and he calls that the best experience for it. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- A 500ms enter animation on every Raycast open would be frustrating. (Great Animations, https://emilkowal.ski/ui/great-animations)
- Elements used constantly are better with no hover animation. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Animations and hover effects seen tens or hundreds of times a day are removed; they become annoying and make the interface feel slower. (7 Practical Animation Tips, https://emilkowal.ski/ui/7-practical-animation-tips)

## Delight

- Delight is a valid purpose only for something users rarely see. His example is a feedback component that morphs. Seen daily, the same motion irritates. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)

## Decoration against function

- Motion tied to the pointer through a spring works only because the element is decorative. (Good vs Great Animations, https://emilkowal.ski/ui/good-vs-great-animations)
- A functional graph, such as one in a banking app, is better with no animation. (Good vs Great Animations, https://emilkowal.ski/ui/good-vs-great-animations)
- Instant change is sometimes the better choice on the web. (Good vs Great Animations, https://emilkowal.ski/ui/good-vs-great-animations)

## Speed as part of the decision

- Outside marketing pages, interface motion must be fast, because speed keeps the interface tied to the user's action. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- Marketing pages are the stated exception to the speed rule. (You Don't Need Animations, https://emilkowal.ski/ui/you-dont-need-animations)
- When most software is good enough, motion is one of the few places left to stand out. (Good vs Great Animations, https://emilkowal.ski/ui/good-vs-great-animations)
